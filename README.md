# Bloom

Мобильный Flutter-прототип личного дневника ручного заваривания кофе. Интерфейс на русском, основной метод — V60. Android, iOS и браузер используют один Dart-интерфейс и одну модель данных.

## MacBook и iPhone 16 Pro

Пошаговый запуск: **[ЗАПУСК_НА_MAC.md](ЗАПУСК_НА_MAC.md)**. Для установленного
Flutter и Xcode начните из папки проекта:

```sh
bash tool/ios.sh doctor
bash tool/ios.sh prepare
bash tool/ios.sh simulator
```

Для физического iPhone сначала выберите свою Team в `ios/Runner.xcworkspace`,
затем выполните `flutter devices` и `bash tool/ios.sh device <device-id>`.
Скрипт не меняет подпись и не устанавливает инструменты автоматически.

В iOS-адаптации добавлены панель «Готово» над клавиатурой, системные диалоги
подтверждения, отступы для Dynamic Island/нижнего индикатора, сохранение черновика
при уходе приложения в фон и обновление таймера при возвращении без запоздалых
звуковых подсказок. Экран запуска поддерживает светлую и тёмную темы. Фото
выбираются без запроса полных метаданных. Интерфейс, журнал и формат базы сохранены.

Результаты текущих проверок и ограничения — в [docs/IOS_CHANGES.md](docs/IOS_CHANGES.md).
Исторические результаты Android/Web ниже относятся к исходному архиву.

## Быстрый запуск

Проверено с Flutter **3.47.7 / Dart 3.13.5**. Зависимости закреплены в `pubspec.lock`.

```sh
flutter pub get
flutter run -d chrome --web-port 8800
```

На этом Windows-компьютере SDK установлен в `C:\Users\Acer\.codex\tools\flutter`. Для запуска из папки с кириллицей используйте обёртку:

```powershell
.\tool\run.ps1
```

Она создаёт короткий путь к той же папке и запускает веб-сервер. Откройте **http://127.0.0.1:8800**. Не меняйте адрес и порт между запусками: браузер хранит данные отдельно для каждого origin. Если порт уже занят работающим прототипом, откройте существующую страницу.

## Сборка

```sh
flutter build web --release --no-web-resources-cdn
flutter run -d <android-device-id>
flutter build apk --release
```

Готовая веб-версия находится в `build/web`. Её нужно раздавать HTTP-сервером, не открывать как `file://`. Для Android нужны JDK 17+, Android SDK и cmdline-tools. Для сборки iOS нужен macOS с Xcode; описание доступа к фотобиблиотеке включено.

Windows-команды: `tool/run.ps1 -Task web`, `-Task android`, `-Task test`, `-Task analyze`.

Android release использует отдельный ключ подписи, а не debug-ключ. Параметры задаются в локальном `android/key.properties`:

```properties
storeFile=C:/path/to/bloom-release.jks
storePassword=YOUR_PRIVATE_PASSWORD
keyAlias=bloom
keyPassword=YOUR_PRIVATE_PASSWORD
```

Ключи и пароли исключены из Git. Сохраните резервную копию ключа и пароля: для обновления уже установленного приложения нужна та же подпись. На текущем компьютере они находятся в `%USERPROFILE%/.android/signing/` (`bloom-release.jks` и `bloom-key.properties`). Не отправляйте эти файлы вместе с APK.

`tool/run.ps1 -Task android` выбирает доступный JDK и собирает release APK. Можно передать `-JavaHome 'C:\path\to\jdk'`; системные настройки Java не меняются. Первый запуск может загрузить недостающие компоненты Android SDK/NDK. Результат Flutter: `build/app/outputs/flutter-apk/app-release.apk`.

20 октября 2026 собран подписанный **Bloom 1.1.0 (3)** для Android 7.0+ (API 24). Готовый универсальный APK: `build/releases/Bloom-1.1.0.apk` (60,0 МиБ; ARM64, ARMv7, x86_64), рядом — файл `Bloom-1.1.0.apk.sha256`. Пакет `app.bloom.bloom`, target SDK 36. Подпись совпадает с версией 1.0.1: устанавливайте обновление поверх неё, сохраняя локальные данные. APK и ключи подписи не включаются в Git.

В версии 1.1.0 добавлены тёмная и системная темы, выбор минут и секунд прокруткой для этапов и результата, оценка горечи и панель выбора пачки в журнале. Обновлены шрифты журнала и оборудования, номер версии отображается в разделе «Оборудование».

Проверены release-сборки Android и Web, подпись через `apksigner`, выравнивание APK для страниц 16 КБ через `zipalign`, 47 автоматических тестов и `flutter analyze` без замечаний. SHA-256 APK: `bfe08c3160e44ebd0248d36420cc8a861f4e8718a71064f5e362fa2ba3535e3b`. Новый APK пока не проверен на физическом Android-устройстве. Сборка iOS требует macOS с Xcode.

## Что работает

- Три вкладки: **Мой кофе / Журнал / Оборудование**.
- Светлая, тёмная и системная тема: **Оборудование → Оформление → Тема**. Выбор сохраняется локально; системная тема следует настройке устройства.
- Добавление пачки с необязательным фото, датами, страной, обработкой и заметками. Редактирование, архив и ручная корректировка остатка.
- Рецепты, привязанные к конкретной пачке. Пропорцию можно редактировать напрямую (например, 1:16): вода и суммарные цели вливаний пересчитываются до целых граммов. Изменение дозы сохраняет выбранную пропорцию, а ручное изменение воды обновляет её. Время автоматически не масштабируется.
- Редактируемые этапы, температура, помол с единицами, оборудование и вода. Проверка возрастающих времён, суммарных весов и последнего целевого веса.
- Время этапов, общий ориентир и фактическое время выбираются колёсами минут и секунд. Изменения применяются по кнопке «Готово»; «Отмена» оставляет прежнее время.
- Таймер по реальному времени, подсказки со звуком по желанию, автоматическая смена этапов. После ориентира таймер продолжает идти. Свёрнутый таймер восстанавливается из баннера, в том числе после перезагрузки.
- Ручная запись без таймера. Фактические параметры, оценка, намерение повторить, вкус и идея следующего эксперимента. Черновик результата сохраняется.
- Необязательные вкусовые оценки: кислотность, сладость, горечь и тело. Они сохраняются в черновике, записи журнала и JSON-экспорте.
- Журнал с фильтрами, любимые чашки, повтор из истории, сохранение попытки отдельным рецептом.
- Выбор пачки в журнале открывает панель с обложками, названиями и обжарщиками, с поддержкой длинных названий и обеих тем.
- Сравнение двух завариваний одной пачки: помол, температура, пропорция, время, оценки и заметки. Различия выделены без автоматических выводов о вкусе.
- Несколько редактируемых наборов оборудования и набор по умолчанию. Экспорт всех данных в JSON через скачивание или системное меню «Поделиться».

Основной путь: **пачка → повторить последнее → поправить параметр → заварить / записать вручную → оценить → сохранить → сравнить**.

## Демонстрационные данные

При первом запуске создаются две вымышленные пачки:

- **Эфиопия Сидамо / Тихий обжарщик**: 250 г, остаток 205 г, три попытки по 15 г. Рецепт «Утренний V60»: 15 / 250 г, 93 °C, Timemore C3, 18 кликов, V60 02, 3:00. Этапы: 0:00 → 45 г; 0:45 → 125 г; 1:15 → 195 г; 1:45 → 250 г.
- **Колумбия Уила / Северный склон**: 200 г, натуральная обработка, без завариваний.

Даты рассчитаны относительно первого запуска: обжарка раньше открытия, открытие раньше завариваний. Данные создаются один раз и не возвращаются поверх пользовательских изменений.

## Хранение и гарантии

SQLite-таблицы: `packs`, `recipes`, `brews`, `settings`. У рецептов и завариваний есть внешние ключи на пачку. Параметры хранятся как JSON-снимки внутри записей SQLite.

- Android/iOS: нативный SQLite через `sqflite`.
- Браузер: настоящий SQLite WASM через `sqflite_common_ffi_web`, файл базы сохраняется в IndexedDB. Worker и WASM включены в репозиторий.
- Сохранение заваривания и списание **фактической** дозы выполняются в одной транзакции. Уникальный ID сессии предотвращает дубли и повторное списание.
- Запуск, отмена и правка рецепта не уменьшают остаток.
- Недостаточный остаток блокирует списание: можно взвесить зерно и уточнить массу.
- Исторический снимок отделён от рецепта-плана. Его редактирование не переписывает прошлые чашки.
- Звук работает при активном приложении; фоновое выполнение звука зависит от ОС/браузера. Сам отсчёт восстанавливается по сохранённому времени начала.
- Облачной синхронизации нет. Очистка данных приложения/сайта удаляет локальную базу; для сохранения копии есть JSON-экспорт. Импорт не входит в эту версию.

## Дизайн

Фон `#F5EFE6`, акцент `#302820`, поверхности `#FFFCF8`, текст `#302820`, вторичный текст `#6F6962`, границы `#E2DAD0`, треки `#E7DFD4`, небольшие детали `#B65A3A`. Базовый экран — 393×852, протестирована также ширина 320 px.

Тёмная палитра: фон `#1E1A17`, карточки и поля `#29231F`, текст `#F5EFE6`, вторичный текст `#B7ADA2`, границы `#463C33`, треки `#38302A`, акцент `#E9DCCB`, текст на акценте `#241E19`, терракота `#D68D6D`. Цвета всех экранов берутся из `ThemeExtension`, включая таймер, формы, фильтры, диалоги и системные панели. Фотографии и цвета упаковки сохраняются.

Inter 400/500/600/700 и IBM Plex Mono 400/600 включены локально, с кириллицей. Текст использует Inter Regular, заголовки — SemiBold/Bold, кнопки — SemiBold. Для числовых параметров используется IBM Plex Mono Regular, для крупного таймера — SemiBold с табличными цифрами. Статические начертания Inter получены из официального variable font Google Fonts (оптический размер 14), без искусственного утолщения. Исходники: [Inter](https://github.com/google/fonts/tree/main/ofl/inter), [IBM Plex Mono](https://github.com/google/fonts/tree/main/ofl/ibmplexmono). Лицензии SIL OFL находятся в `assets/fonts`. Обложки пачек рисуются кодом; изображения из сети не нужны.

Иконка приложения создаётся из предоставленного `assets/brand/app-icon-source.png`. Для Android предусмотрены тёплый фон на Android 7 и adaptive icon на Android 8+, для iOS — непрозрачный AppIcon. Генератор: [flutter_launcher_icons](https://pub.dev/packages/flutter_launcher_icons), настройки в `flutter_launcher_icons.yaml`. Повторная генерация после `flutter pub get`: `python tool/brand_assets.py`. Обёртка сохраняет отдельную настройку Xcode, которую генератор 0.14.4 иначе затрагивает.

## Проверка

```sh
flutter analyze
flutter test
```

Тесты проверяют пересчёт и округление, границы этапов таймера, проверку форм, размеры экранов, восстановление сессии, неизменность истории, отсутствие двойного списания, откат транзакции при недостаточном остатке, архив и набор оборудования.

## Структура

- `lib/domain.dart` — числа, время, этапы и шаблон рецепта.
- `lib/database.dart` — SQLite-схема и выбор реализации.
- `lib/store.dart` — сохранение, транзакции, демоданные и экспорт.
- `lib/design.dart` — палитра, типографика и общие компоненты.
- `lib/palette.dart` — токены светлой и тёмной темы.
- `lib/screens/` — пачки, рецепты, таймер, результат, журнал и оборудование.
- `test/` — проверки логики, SQLite и интерфейса.
- `tool/` — Windows-запуск, генерация иконок и исходник SQLite-worker.

Веб-ресурсы SQLite уже готовы. При обновлении `sqlite3` пересоберите worker с согласованной версией и обновите WASM, затем проверьте сохранение после перезагрузки. Обычный запуск не требует генерации этих файлов.
