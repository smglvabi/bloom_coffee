# Изменения для iOS

Адаптация из пользовательского `bloom-main.zip` для разработки на MacBook и
запуска на iPhone 16 Pro. Руководство: [ЗАПУСК_НА_MAC.md](../ЗАПУСК_НА_MAC.md).

## Что изменено

- Кнопка «Готово» над клавиатурой iOS с резервированием места в форме и
  увеличением высоты при крупном системном тексте. Нажатие вне поля скрывает
  клавиатуру; цифровые поля получают действие завершения ввода.
- Системные Cupertino-диалоги для общих подтверждений и поддержка VoiceOver
  у кнопок вкладок. Фирменная светлая/тёмная палитра сохранена.
- Отступы над нижним индикатором iPhone у отдельных форм и страниц деталей;
  дополнительная защита главного экрана, когда активный таймер скрывает вкладки.
- Таймер обновляется по времени начала после возвращения из фона. Пропущенные
  этапы не сопровождаются запоздалыми звуками. Фоновые уведомления не добавлены.
- Черновик результата отправляется в SQLite при уходе в фон, не дожидаясь
  задержки автосохранения. Записи выполняются последовательно, чтобы поздняя
  запись не восстановила сессию после сохранения или удаления чашки.
  Если запись не удалась, действие «Сохранить позже» оставляет форму открытой
  с последними изменениями и предлагает повторить сохранение.
- При выборе фото не запрашиваются полные метаданные. Сообщение об ошибке базы
  на телефоне больше не предлагает менять настройки браузера.
- В Xcode включена автоматическая подпись без чужой Team; основной язык проекта
  — русский. Обновлён экран запуска в обеих темах. Сохранены iOS 15+, поддержка
  iPad, существующий Bundle Identifier и Swift Package Manager.
- Добавлен `tool/ios.sh`: диагностика, подготовка, симулятор, физический iPhone,
  анализатор и тесты. Скрипт не меняет подпись, не устанавливает инструменты и
  использует `flutter pub get --enforce-lockfile`.

Схема SQLite, формат журнала, `pubspec.yaml`, `pubspec.lock`, шрифты и основные
сценарии приложения сохранены. Отдельный бэкенд и облачная синхронизация не
добавлены. Ключей, профилей подписи и учётных данных в архиве нет.

## Проверки этой адаптации

В текущем Linux-окружении выполнены:

- `bash -n tool/ios.sh` — успешно.
- `python3 -m unittest discover -s test -p 'tool_ios_test.py' -v` — **9 тестов
  скрипта прошли**. Они подменяют команды Xcode/Flutter, проверяют выбор нужного
  устройства, создание симулятора, отказ при отсутствии runtime, использование
  lockfile и остановку при ошибке зависимости. Это не тест нативной сборки.
- Статический разбор Dart-файлов через tree-sitter — синтаксических ошибок нет.
  Он не заменяет `flutter analyze` и проверку типов.
- Разбор plist/JSON/XML и ссылок проекта Xcode — успешно. Основная иконка iOS
  1024×1024 проверена на отсутствие прозрачности.

**Не выполнены:** `flutter analyze`, `flutter test`, нативная iOS-сборка и
запуск на реальном iPhone. В облачном окружении нет Flutter SDK; загрузка с
`storage.googleapis.com` возвращает HTTP 403 сетевого прокси. Xcode недоступен
на Linux. Исторические результаты исходного README не относятся к этой
адаптации и не подтверждают её сборку.

Добавлены, но ещё не исполнены Flutter-проверки:

- `test/ios_adaptation_test.dart`: клавиатура, нативное подтверждение, безопасная
  область iPhone 16 Pro 402×874 и отдельные страницы при масштабе текста 130%.
- `test/lifecycle_test.dart`: сохранение черновика при неактивности, завершение
  ожидающей записи перед сохранением чашки, возврат таймера без устаревшего звука
  и сохранность введённого текста при ошибке записи с успешной повторной попыткой.

На вашем Mac выполните:

```sh
bash tool/ios.sh check
flutter build ios --simulator --debug
bash tool/ios.sh simulator
```

Затем выберите свою Team и проверьте на iPhone фото, системный экспорт в «Файлы»,
звук, сворачивание/возврат, сохранение и повторное открытие журнала. Нативные
плагины нельзя полностью проверить widget-тестами. Для текущих плагинов
CocoaPods не требуется: нативные плагины поддерживают SPM, а
`path_provider_foundation` использует Dart FFI.
