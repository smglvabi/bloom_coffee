# Bloom на MacBook и iPhone 16 Pro

Это исходный проект приложения для iOS, а не подписанный IPA. Установить его на
ваш iPhone нужно с вашего MacBook: Xcode подпишет приложение вашей учётной записью.
Сервер, регистрация и ключи API не нужны. Данные хранятся локально в SQLite.

## 1. Подготовьте инструменты

Xcode и Flutter у вас уже установлены. Откройте **полный Xcode** один раз,
завершите установку компонентов и примите его лицензию. В **Xcode → Settings →
Locations → Command Line Tools** выберите установленную версию Xcode.

В Terminal проверьте:

```sh
flutter --version
xcodebuild -version
```

Для закреплённых зависимостей нужен **Flutter 3.47.0+ / Dart 3.13.0+**;
исходный архив подготовлен под **Flutter 3.47.7 / Dart 3.13.5**. Предпочтительно
использовать Flutter 3.47.7. Если ваша версия старше, обновите stable SDK через
`flutter channel stable` и `flutter upgrade` либо установите отдельную нужную
версию SDK. Скрипт не обновляет SDK автоматически и не меняет `pubspec.lock`.
Если более новый SDK несовместим с закреплёнными пакетами, используйте 3.47.7,
а обновление пакетов выполняйте отдельно.

Нужен Xcode, поддерживающий установленную iOS на телефоне. Если Xcode сообщает
о неподдерживаемой версии iOS, обновите Xcode; иногда для этого требуется
обновление macOS. Для симулятора установите iOS runtime в **Xcode → Settings →
Components** (в некоторых версиях раздел называется **Platforms**).

Текущие нативные плагины используют Swift Package Manager. Отдельная установка
CocoaPods для этой версии не требуется. Интернет нужен при первой загрузке
Flutter/iOS-компонентов и пакетов; затем основной функционал работает офлайн.

## 2. Откройте папку приложения

Распакуйте полученный архив в удобное место, например `~/Projects/bloom-ios`.
В Finder откройте папку, где лежит `pubspec.yaml`, и откройте для неё Terminal.
Либо введите путь вручную, например:

```sh
cd "$HOME/Projects/bloom-ios"
bash tool/ios.sh doctor
bash tool/ios.sh prepare
```

Первая команда показывает состояние инструментов и устройств. Вторая загружает
iOS-артефакты и зависимости и генерирует локальные настройки проекта без подписи.
Сообщения `flutter doctor` об Android SDK/Chrome не мешают сборке для iPhone.

## 3. Сначала проверьте в симуляторе

```sh
bash tool/ios.sh simulator
```

Скрипт выбирает доступный симулятор **iPhone 16 Pro** или создаёт его для
установленного iOS runtime, ждёт загрузки и запускает приложение. Симулятор не
требует Apple Developer Account или настройки подписи. Если устройств несколько,
можно передать UDID конкретного симулятора.

При отладке клавиша `r` в Terminal применяет изменения Flutter, `R` полностью
перезапускает приложение, `q` завершает сеанс запуска.

## 4. Настройте подпись для своего iPhone

1. Подключите разблокированный iPhone 16 Pro кабелем к MacBook. На телефоне
   подтвердите **«Доверять этому компьютеру»**.
2. Откройте **Xcode → Settings → Accounts** и добавьте свой Apple Account.
3. Из папки проекта выполните:

   ```sh
   open ios/Runner.xcworkspace
   ```

4. В Xcode выберите проект **Runner**, затем **TARGETS → Runner → Signing &
   Capabilities**. Включите **Automatically manage signing** и выберите свою
   **Team**. Не меняйте Team проекта RunnerTests вместо основного Runner.
5. Если `app.bloom.bloom` недоступен вашей команде, задайте уникальный
   **Bundle Identifier**, например `com.yourname.bloom` (замените
   пример своим идентификатором с латинскими буквами, без пробелов). Изменение
   идентификатора создаёт отдельное приложение со своей локальной базой.
6. На iPhone включите **Настройки → Конфиденциальность и безопасность → Режим
   разработчика**, если Xcode запрашивает это. Следуйте предложению перезагрузить
   телефон. Если пункта ещё нет, сначала выполните подключение устройства в
   **Xcode → Window → Devices and Simulators**.
7. Выберите iPhone в списке устройств Xcode. Дождитесь окончания подготовки
   устройства. Если требуется доверие профилю разработчика, подтвердите его в
   **Настройки → Основные → VPN и управление устройством** на iPhone.

Для личной установки обычно достаточно бесплатной **Personal Team**. Такая
подпись обычно действует 7 дней: затем снова соберите и установите приложение
с тем же Bundle Identifier и Team. Для TestFlight и App Store нужна платная
учётная запись Apple Developer. Этот проект не публикуется автоматически.

## 5. Запустите на iPhone

Получите идентификатор устройства:

```sh
flutter devices
```

Запустите, подставив ID именно физического iPhone из списка:

```sh
bash tool/ios.sh device ВАШ_DEVICE_ID
```

Скрипт использует **release**: установленное приложение можно открывать с иконки
на телефоне без подключённого отладчика. Условия подписи Personal Team продолжают
действовать. Для разработки с hot reload используйте:

```sh
flutter run -d ВАШ_DEVICE_ID
```

Если Flutter не обнаруживает телефон, откройте **Xcode → Window → Devices and
Simulators**, проверьте доверие и сопряжение, затем повторите `flutter devices`.
Начните с подключения кабелем; беспроводной запуск настройте после успешного
первого запуска. При ошибках подписи проверьте Team, Bundle Identifier,
доступность Apple Account и подключение Mac к интернету.

## 6. Проверьте основные функции

- Откройте демонстрационную пачку, запустите рецепт и включите подсказки.
- Сверните приложение, затем вернитесь: время должно учитывать прошедший интервал.
  Звук этапов работает в активном приложении; фоновых уведомлений и Live Activities
  в этой версии нет. Тихий режим и громкость могут влиять на звук.
- Введите заметку к чашке, сверните приложение, вернитесь и проверьте черновик.
  iOS может мгновенно завершить процесс; не используйте принудительное завершение
  как способ сохранения незаписанных данных.
- Сохраните чашку: она должна появиться в журнале, а остаток кофе уменьшиться
  один раз на фактическую дозу.
- Добавьте фото из галереи. В iOS Simulator лучше использовать JPEG/PNG;
  отдельные форматы HEIC надёжнее проверять на настоящем iPhone.
- Проверьте светлую и тёмную темы, цифровую клавиатуру и кнопку **«Готово»**.
- В **Оборудование → Экспортировать журнал** выберите системное действие
  **«Сохранить в Файлы»**. Экспорт JSON — резервная копия для чтения/переноса;
  автоматического импорта в этой версии пока нет.

Не удаляйте приложение для исправления ошибок: вместе с ним удаляются локальные
записи. Симулятор, iPhone и веб-версия имеют отдельные базы; синхронизации между
Mac и iPhone нет. На Mac приложение можно разрабатывать и запускать в симуляторе;
отдельной сборки для рабочего стола macOS в этом проекте нет.

## Автоматические проверки

```sh
bash tool/ios.sh check
flutter build ios --simulator --debug
```

`check` проверяет закреплённые зависимости, запускает `flutter analyze` и
`flutter test`. Последняя команда отдельно проверяет нативную сборку без подписи.
После неё обязательно проверьте фото, экспорт и звук на физическом устройстве:
widget-тесты не проверяют системные плагины iOS.

Если уже знакомы с Flutter, команды без обёртки:

```sh
flutter precache --ios
flutter pub get --enforce-lockfile
flutter build ios --config-only --no-codesign
open ios/Runner.xcworkspace
flutter devices
flutter run --release -d ВАШ_DEVICE_ID
```

Официальная справка: [подготовка Flutter для iOS](https://docs.flutter.dev/platform-integration/ios/setup).
